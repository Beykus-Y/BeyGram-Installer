# Signing and renewal

| Concern | Existing implementation |
|---|---|
| Apple login | `crates/plume_core/src/auth/account/login.rs` implements `Account::login`, `login_with_anisette` and `login_email_pass` for GrandSlam/SRP. `two_factor_auth.rs` implements trusted-device and SMS requests and verification. `token.rs::get_app_token` obtains an app token, and `developer/session.rs::DeveloperSession::using_account` constructs a developer session. |
| Anisette | `auth/anisette_data.rs::AnisetteData` generates headers and tracks age. `3rdparty/omnisette/src/lib.rs::AnisetteHeaders::get_anisette_headers_provider` selects a provider. See [Security](SECURITY.md) for trust boundaries. |
| IPA and modifications | `apps/plumeimpactor/src/subscriptions.rs::run_installation` orchestrates GUI installs, while `apps/plumesign/src/commands/sign.rs` uses the same workspace signing code. `plume_utils/src/package.rs::Package` handles archive extraction. `Signer::modify_bundle` edits metadata and features, with explicit `SignerOptions::custom_identifier` or a default original ID suffixed by Team ID in non-ad-hoc signing. `Bundle::set_matching_identifier` applies changes to matching nested IDs. |
| Registration | `plume_utils/src/signer.rs::Signer::register_bundle` collects signable apps and extensions, calls `qh_ensure_app_id` and looks up the returned App ID. `plume_core/src/developer/qh/app_ids.rs` implements lookup/create. `developer/v1/capabilities.rs::v1_request_capabilities_for_entitlements` translates supported capabilities. Group registration and assignment call `qh_ensure_app_group` and `qh_assign_app_group` from `developer/qh/app_groups.rs`. Existing incoming group names are suffixed with the Team ID on fresh signing, so two channels sharing an input group can still collide. |
| Profiles and entitlements | `developer/qh/profile.rs::qh_get_profile` obtains the encoded provisioning profile. `register_bundle` writes each selected app or extension profile into its cached bundle and stores parsed profiles. `utils/provision.rs::MobileProvision::merge_entitlements` and `utils/macho.rs::MachO` reconcile entitlements before signing. `Signer::sign_bundle` applies the certificate and calls vendored `apple-codesign`. Its profile selection can fall back to the first profile when no ID matches. That fallback needs explicit coverage for multiple extensions. |
| Extensions | `plume_utils/src/bundle.rs::Bundle::collect_bundles_sorted` enumerates nested bundles. `BundleType` distinguishes app, extension, framework and other signing inputs. `SignerEmbedding::single_profile` can suppress separate profile registration for nested targets. Framework signatures and extension profiles have different roles. |
| Certificates | `plume_core/src/utils/certificate.rs::CertificateIdentity::new_with_session` loads local key material and attempts certificate reuse or issues a CSR. `developer/qh/certs.rs` lists, submits and revokes. `CertificateIdentity::create_pkcs12` packages a private key and certificate. The quota fallback has an account-wide impact described in [Security](SECURITY.md). |
| Installation | `plume_utils/src/device.rs::Device::install_app` passes an app bundle via the `idevice` installation helper. Apple Silicon local installation uses `install_app_mac`. |

## Quick and full renewal

`apps/plumeimpactor/src/refresh.rs::RefreshDaemon::refresh_app` uses the stored account, team, cached app and effective bundle ID. If the identity is new, the device is a Mac or the app is absent, `resign_and_reinstall` re-registers profiles, signs and installs the cached app. Otherwise `update_provisioning_profiles` calls `register_bundle` with refresh mode and sends each profile through `Device::install_profile` (misagent). There is no device-side readback or proof that the installed app launches with the renewed profiles. The choice relies on identity freshness and app presence, without comparing the installed signing identity or entitlements. Profile-only failure returns an error and is retried by later polling. It does not immediately fall back to reinstall.

`update_refresh_schedule` reads the refreshed cached main `embedded.mobileprovision`, then schedules three days before expiration. The main profile is rewritten during registration. A failed multi-profile operation can still modify some cached files. Extension expiry and installed profile state are outside this schedule calculation.

## Issue #2 acceptance work

Inspect both actual IPA files and record root and nested IDs, build versions, signing entitlements, groups, Keychain entries, URL schemes and frameworks. Save a deterministic mapping scoped to Apple Team and channel for the main app and every retained extension. Check quota impact before mutation and verify reuse by measuring Apple-side App IDs before and after repeat updates. Reject a missing profile match and require explicit handling of unsupported capabilities.

Test both channels on one modern physical iPhone with an authorized dedicated Personal Team. Verify cold launch, simultaneous operation, independent data, Keychain, groups and push registration where applicable. Update each app over its previous version and verify its session and data survive. Exercise interrupted updates and exhausted certificate/App ID quotas without uninstalling an existing app or revoking unrelated certificates. Record iOS and desktop versions, effective IDs and observed capabilities without secrets. Treat renewal eligibility and Release priority as later acceptance gates. There is no channel map, verified feed, priority queue or guaranteed update transaction in the baseline.
