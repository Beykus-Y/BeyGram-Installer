# MVP 0 Foundation report

Impactor v2.7.3 at `2ba32ea43246bd4db0265eb3120d3c72e39f5b22` is the latest stable revision and matched upstream main when selected. DEV retains the original BeyGram and Impactor histories through merge `bc0320389fe6d540b28a291c757c91c39d3ecffe`. The Foundation changes are on [Draft PR #10](https://github.com/Beykus-Y/BeyGram-Installer/pull/10).

The imported tree contains an Iced desktop GUI, Clap CLI, four internal crates and vendored components. Impactor is a viable basis for signing and USB installation. Its team-suffixed ID scheme, App ID reuse, extension registration, profile installation and tray integration are useful starting points. Windows automation needs a tested transport and shared operation locks. The existing scheduler and cache do not encode Release priority, channel-specific identity, trusted package feeds or durable retries.

The largest blockers for real-account testing and distribution are TLS verification in Anisette, unencrypted token/key storage, quota-triggered certificate revocation, untrusted archive extraction and unresolved redistribution terms. Both workspace binaries built and Clippy completed with warnings on all three native CI runners after the portability fix. The local Debian container also built both binaries. Rustfmt and the two Anisette integration checks fail. Details and local results are indexed in [Build](BUILD.md). See [Security](SECURITY.md) and [Licensing](LICENSES.md) for source evidence.

Issue #2 should inspect the actual pair of IPA artifacts, map every retained bundle to a stable team-scoped channel identity, preflight App ID and certificate quotas and verify simultaneous installation and in-place updates on an authorized physical iPhone. See the explicit [acceptance work](SIGNING.md#issue-2-acceptance-work). A device or account failure must preserve the previous installation. Windows wireless reconnection and automatic servicing remain later stages.
