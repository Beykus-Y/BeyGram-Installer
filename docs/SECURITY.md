# Security review

Static review of v2.7.3. Severity P0 means a release-blocking trust failure, P1 a high-impact exposure or destructive operation, P2 a narrower hardening or reliability issue, and P3 a lower-priority verification gap. The review used no user credentials or device records.

| Priority | Finding and evidence | Acceptance condition for later work |
|---|---|---|
| P0 | Anisette HTTP certificate verification is explicitly disabled in `3rdparty/omnisette/src/remote_anisette_v3.rs::make_reqwest` and the local provider's Apple lookup in `adi_proxy.rs`. The remote path uses that client for service metadata and Apple provisioning HTTP. It also follows provisioning URLs supplied by the lookup. WebSocket transport is separate. | Verify server certificates for all HTTP paths and constrain trusted endpoints. Exercise rejection with synthetic TLS fixtures. |
| P1 | `crates/plume_store/src/gsa_account.rs::GsaAccount` stores email, first name, ADSID, Xcode GS token and team. `store.rs::AccountStore::{save,save_sync}` writes ordinary JSON. `apps/plumeimpactor/src/defaults.rs::get_data_path` uses APPDATA or XDG configuration. Upstream has no OS credential vault or explicit restrictive ACL in these writes. | Protect developer tokens in OS credential storage, migrate existing state and test logout/revocation and metadata permissions. |
| P1 | `crates/plume_core/src/utils/certificate.rs::CertificateIdentity::new_with_session` writes clear PKCS#8 PEM under `keys/<team_id>/key.pem`. `create_pkcs12` uses an empty export password. GUI `subscriptions.rs::export_certificate` stages a P12 in the data directory, and `Signer::modify_bundle` embeds credential material in certain third-party integration flows. | Protect keys at rest, require explicit export and ensure export/staging cleanup. Exclude third-party credential embedding from BeyGram defaults. |
| P1 | `CertificateIdentity::request_new_certificate` reacts to quota error 7460 by trying serials from the full team list. GUI and refresh pass `certificate_reset::confirm`. CLI `commands/sign.rs` passes no callback, so it can attempt revocation without user confirmation. A candidate can belong to another installation or workflow. | Prohibit revocation during automatic servicing and on quota exhaustion. Require explicit ownership checks and consent for a manual certificate replacement. |
| P1 | `3rdparty/omnisette/src/lib.rs::AnisetteHeaders::get_anisette_headers_provider` silently falls back from StoreServicesCore to a third-party v3 provider. `remote_anisette_v3.rs` exchanges client/provisioning data and provisioning intermediates over HTTP/WebSocket and persists state through its configuration path. The Apple password path is GrandSlam in `crates/plume_core/src/auth/account/login.rs`. The remote provider still requires a documented trust decision and lifecycle. | Document which provider is active, disclose endpoint and data categories, and require an approved provider configuration before unattended operation. |
| P1 | Standard pairing material is managed via usbmuxd in `plume_utils/src/device.rs::Device::pair`. Its app-container integration exports a record, and `get_rsd_pairing_file` caches a remote-pairing plist with ordinary file writes. `install_pairing_record` attempts to enable wireless lockdown and ignores that setting's error. | Keep host pairing on the OS transport path, restrict files, verify wireless configuration and exclude pairing files from logs, diagnostics and uploads. |
| P2 | The GUI login window keeps transient password `String` copies and clears the field on submit. The account schema has no password field. CLI `commands/account.rs` accepts `--password`, which can expose it to shell history or process inspection. | Prefer interactive masked entry, limit copies and lifetime, and verify synthetic secrets never reach persistent state. |
| P2 | `plume_core/src/developer/session.rs` logs QH/V1 request and response bodies at debug level. Refresh messages include local file paths, UDIDs and potentially account email in errors. Request headers and payloads require separate review before diagnostics are exported. | Redact identifiers and sensitive payloads by default and test logging with synthetic fixtures. |
| P2 | The refresh worker inherits the GUI user's privileges. Autostart uses current-user settings on Windows. Shared mutable JSON, separate daemon instances and multi-profile partial writes create a risk of lost state or misleading success. | Use shared device locking, atomic persistence and verified profile readback. Keep background actions within the user session and authorize any future IPC explicitly. |
| P3 | GrandSlam and DeveloperSession use reqwest with HTTPS. The workspace enables system proxies and the Windows core manifest enables native TLS due to the upstream platform-verifier issue. Effective trust stores and proxy behavior have not been exercised on each OS. | Verify certificate rejection and proxy behavior with test endpoints and record the active TLS backend on each OS. |
