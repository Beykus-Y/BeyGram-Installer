## Locked dependency graph

`cargo metadata --locked --format-version 1` resolved 938 packages across targets and build/test dependencies on Rust 1.100.0. The manifest review includes permissive MIT, Apache, BSD, ISC, Unicode and Zlib notices, MPL file-level terms, root certificate data under CDLA, and the following open questions:

- `remove-async-await 1.0.1` declares AGPL-3.0 and enters the build as an Omnisette procedural macro. Verify generated-code obligations and whether any macro implementation is incorporated in shipped artifacts. A build-time dependency alone does not establish the license of the resulting installer.
- `android-loader 0.2.0` and its `sysv64 0.1.0` macro declare no license in the locked manifests. Their checked-out source at `dfa86501` has no root license text. Resolve permission before distribution.
- Where `self_cell` offers Apache-2.0 OR GPL-2.0-only or `r-efi` offers a permissive alternative to LGPL, review the chosen license per artifact. AppImage shared libraries and bundled compression/native components require inventory outside Cargo metadata.

Reproduce with `cargo metadata --locked --format-version 1` and `cargo tree --locked --target all -i <crate>`. Before packaging, generate a per-artifact SBOM and notice bundle covering Cargo, native libraries and assets. Confirm source availability and unresolved permissions. This source review does not clear binary redistribution.

## Binary distribution release gate

1. **Resolve the local Anisette loader first.** Request written licensing and binary redistribution terms from the copyright holders for `android-loader` and `sysv64` at `dfa86501`. Record the grant with the exact revisions and required notices. If the grant is unavailable, remove both from distributed binaries and replace the local Anisette implementation with a legally distributable provider. Confirm separately whether StoreServicesCore and its supporting Apple libraries can be redistributed. Until permission is documented, omit the Apple binaries and their download artifacts from all BeyGram packages and use lawfully obtained libraries for development checks.
2. **Resolve vendored and generated code.** Compare Omnisette and Decompress against their upstream revisions file by file. Correct the package license declarations after recording provenance. Preserve MPL-2.0 and Apache-2.0 texts, any upstream NOTICE, and Apache change markings. Publish the exact modified MPL source corresponding to each release and include a source URL in the binary notice bundle. Inspect `remove-async-await` expansion and terms. Remove the dependency by migrating Omnisette callers to the existing async implementation if the AGPL question remains unresolved.
3. **Prove provenance of packaged assets.** Rebuild ElleKit from an exact licensed source revision or obtain an upstream artifact with a verified digest and corresponding license. Check the embedded compatibility framework independently. Include all required BSD notices or exclude ElleKit and its feature from release artifacts. Obtain provenance and redistribution terms for the custom icon font and artwork or replace the assets. Preserve the full Hack font notices.
4. **Inventory each artifact.** Generate an SBOM from the locked Cargo graph for every target and enabled feature set. Inspect the staged NSIS payload, macOS application/DMG and Linux AppImage for additional native libraries, bundled compression code, roots, fonts and artwork. Record which files and dependency licenses actually ship. Include applicable source offers and relinking or replacement instructions for any bundled LGPL libraries. Confirm rights for any Apple Windows runtime component or leave installation to Apple's official distribution channel.
5. **Verify the staged artifacts before publishing.** The release reviewer checks the exact-source link, package-level notices, per-platform SBOM and inventory against each staged artifact. Keep publishing blocked if any shipped component has unresolved permission or missing required notices.

The new vault integration adds platform-specific dependencies through `keyring` and the Linux Secret Service DBus bindings. Include their selected license texts, ring and its bundled notices, and the packaged DBus library if it is included in the final artifact.
